# FitApp

Personal, single-user nutrition + gym log. Installable PWA for Android Chrome. All data stays on the phone (IndexedDB), with JSON export/import as backup. The full spec is in [CLAUDE.md](CLAUDE.md).

## Develop

Requires Node.js (LTS).

```bash
npm install
npm run dev      # local dev server
npm test         # unit tests (Vitest)
npm run build    # production build into dist/
npm run preview  # serve the production build locally
npm run icons    # regenerate the PNG app icons in public/
```

## Deploy to GitHub Pages (one-time setup)

The workflow in `.github/workflows/deploy.yml` tests, builds and deploys the app on every push to `main`. It sets the Vite `base` to `/<repo name>/` automatically, so any repo name works (except `<username>.github.io`).

1. **Create the repository.** Go to <https://github.com/new>.
   - Repository name: `fitapp` (any name works).
   - Visibility: **Public** (GitHub Pages is free only for public repos on a free account). Your data is never in the repo; it only lives on your phone.
   - Do **not** tick "Add a README", ".gitignore" or "license" (the repo must be empty).
   - Click **Create repository**.
2. **Enable Pages with GitHub Actions.** In the new repo: **Settings** -> **Pages** (left sidebar). Under **Build and deployment** -> **Source**, choose **GitHub Actions**. Nothing else to configure.
3. **Push the code.** In a terminal in this folder (replace `YOUR_USER`):
   ```bash
   git remote add origin https://github.com/YOUR_USER/fitapp.git
   ```
   ```bash
   git push -u origin main
   ```
   The first push opens a browser window to sign in to GitHub (Git Credential Manager). Approve it.
4. **Watch the deploy.** Open the repo's **Actions** tab. The "Deploy to GitHub Pages" run should turn green in about 1 to 2 minutes. If it failed because Pages was not enabled yet, do step 2, then open the workflow and click **Run workflow** (or **Re-run all jobs**).
5. **Open the app.** URL: `https://YOUR_USER.github.io/fitapp/` (also shown in **Settings** -> **Pages** and on the finished run).
6. **Install on Android.** Open the URL in Chrome -> menu (three dots) -> **Add to Home screen** / **Install app**.

**Updates:** push to `main`. The installed app downloads the new version in the background; close and reopen it to get it (sometimes twice).

## Decisions

Ambiguities resolved with the simplest option:

- **Spec file name:** the spec arrived as `CLAUDE (2).md`; renamed to `CLAUDE.md` (content unchanged).
- **Vite base:** set from the repo name by the deploy workflow (`VITE_BASE=/<repo>/`) instead of hard-coding it, so renaming the repo cannot break the site. Locally the base is `/`.
- **Remembering the mode:** stored in `localStorage` (not IndexedDB) so the right colors apply before the first paint, with no green/red flash.
- **Routes:** nutrition screens live under `#/n/...`, gym screens under `#/g/...`, Settings at `#/settings`. Settings keeps the current mode's theme and bottom nav. Tapping the mode switch goes to that mode's first screen.
- **Bottom navigation:** Nutrition = Today, Add, Stats, Foods (Foods also holds saved meals). Gym = Workout, History, Exercises, Routines (per-exercise progress and running charts are reached from Exercises).
- **Settings inputs** save when the field loses focus or Enter is pressed. Empty or invalid input reverts to the saved value.
- **Export** downloads `fitapp-backup-YYYY-MM-DD.json`; "last backup" is the time of the last export. **Import** uses the browser's confirm dialog and replaces every table.
- **Persistent storage:** `navigator.storage.persist()` is requested at startup; Settings shows whether the browser granted it (Chrome usually grants it once the app is installed).
- **Database schema:** all tables for both modes are created in version 1 now, to avoid a migration between phases.
- **App icon:** generated by `scripts/make-icons.mjs` (half emerald, half red), no image tooling needed.
- **CI Node version:** 24 (LTS).

### Nutrition (Phase 2)

- **Past logs read food values live.** A meal stores the food id and grams, not a copy of the nutrients. Editing a food (built-in or custom) therefore changes every past day that uses it.
- **Seed values:** built-in foods come from USDA SR Legacy. Some values are estimates because the USDA API rate-limited the fetch. See [SEED_NOTES.md](SEED_NOTES.md). Built-in foods are added once, on first launch.
- **Current meal basket** is saved in `localStorage`, so a half-built meal survives closing the app. The date and time to log under start as the day you came from (Today's day picker) and the current time.
- **Times before 04:00** belong to the previous nutrition day. For example, logging at 01:30 on the 18th's nutrition day stores 01:30 on the 19th's calendar date.
- **Day picker** cannot go past today. Past days open with `?day=`, and Add then logs into that day.
- **Saved meals** store grams in each food's base state (raw/dry/as is). Adding a saved meal puts its items in the basket in grams, scaled by the multiplier. Names are asked for with the browser's prompt dialog.
- **Editing a meal** (tap it in the journal) lets you change date, time and each item's quantity, unit and raw/cooked, remove items, add items (foods or saved meals), or delete the meal. Removing the last item asks to delete the meal.
- **Empty search** shows Recent (last 8 distinct foods logged) and Frequent (8 foods in the most meals). Both are drawn from the last 300 meals. Saved meals appear only when searching.
- **Custom foods** choose whether their values are per 100 g raw, dry or as is. A blank micro field means "no data" (not 0), and the totals then show "Some items have no micro data".
- **Delete vs archive:** a food used in any logged or saved meal can only be archived. Archived foods are hidden from search and listed under "Show archived foods" in Foods, where they can be unarchived. Unused foods (including built-in ones) can be deleted.
- **Stats periods** end today: Day = today, 7 days = today and the 6 days before it, 30 days likewise. Averages divide by logged days only. Today counts once it has a meal.
- **Progress bars** fill up to 100% and stop there; the percentage shows the real value. All bars use the theme accent, with no good/bad colors.
